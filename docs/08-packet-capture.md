# Packet Capture

## 1. Overview

The On-Demand Packet Capture API allows users to schedule and retrieve network packet capture tests on specific sensors. This enables real-time data by capturing packets directly from network sensors.

> **Note:** Sensors will capture 802.11 frames, not Ethernet packets.

API supports:

- Triggering a packet capture test on sensors
- Checking the status of an ongoing/completed packet capture test
- Downloading the packet capture data file

## 2. Endpoints

### `POST /on-demand-test/sensors/{sensorId}/packet-capture`

Starts a packet capture test on a sensor.

> **Note:** Fetch the `sensorId` from the `/eyes/sensors` endpoint.

Select either **Channel Mode** or **Access Point Mode**.

> **Note:** Access Point Mode requires an `accessPointId`. Retrieve this from `/access-points/sensors` using the `sensorId`.

**Request — Channel Mode:**

```json
{
  "mode": "CHANNEL",
  "captureTimeSeconds": "10",
  "captureFilter": "",
  "band": 5,
  "channel": 36
}
```

**Request — Access Point Mode:**

```json
{
  "mode": "ACCESS_POINT",
  "accessPointId": "1234",
  "captureTimeSeconds": "10",
  "captureFilter": ""
}
```

**Response:**

```json
{
  "testId": "string",
  "status": "REQUESTED"
}
```

> **Important:** Capture the `testId` from the response. It is required to check capture status and download results.

### `GET /on-demand-test/sensors/{sensorId}/packet-capture/{testId}`

Retrieves the status of the packet capture test. Requires both `sensorId` and `testId`.

**Response:**

```json
{
  "testId": "string",
  "runStatus": "COMPLETE",
  "testStatus": "OK",
  "captureStatus": "SUCCESS"
}
```

### `GET /on-demand-test/sensors/{sensorId}/packet-capture/{testId}/download`

Downloads the packet capture file generated by the test. Requires both `sensorId` and `testId`.

Poll for `runStatus: "COMPLETE"` before attempting to download.

## 3. Developer Tips

- **Channel Mode** collects all data on the specified channel. **Access Point Mode** captures only traffic to and from a specific access point.
- The `captureFilter` field uses [tcpdump / pcap-filter syntax](https://www.tcpdump.org/manpages/pcap-filter.7.html).
- Poll `GET .../packet-capture/{testId}` for completion before attempting to download the file.
- Tests do not start immediately if an automated test is already running. Requested tests run only after the previous automated test completes.

## 4. Troubleshooting & FAQs

**Q: What format is the packet capture file?**

A: The file is in PCAP format, compatible with tools like Wireshark.

**Q: How long does a packet capture test run?**

A: The packet capture will take a few minutes to be queued and started, depending on the state of automated testing in progress. Once the capture begins, it will complete within the timeframe specified in `captureTimeSeconds`.
